# Backend Development Prompt — FastAPI Hotel Menu System

```text
You are a senior Python backend engineer.

Build a production-ready REST API backend for a Hotel Digital Menu / Restaurant Menu Display System.

The system is NOT an online ordering system.

The customer workflow is:

1. Customer enters the hotel/restaurant.
2. Customer scans a QR code placed on the table / room / location.
3. QR code opens the digital menu website.
4. Customer can browse menu categories and menu items.
5. Customer can search menu items.
6. Customer can see item images, descriptions, prices, ratings and availability.
7. If an item becomes OUT OF STOCK, the admin can update it from the admin panel.
8. The customer's menu screen should update the availability live without requiring a manual refresh.
9. Customer can submit a review/rating.
10. Customer can rate the serving/waiting staff member who served them.
11. Admin can manage menu items, categories, banners, staff, QR locations, reviews and availability.

There must be NO:
- Shopping cart
- Order creation
- Checkout
- Payment
- Food ordering
- Order tracking
- Delivery
- Inventory management
- Billing

This is strictly a digital menu + review + staff rating system.

==================================================
TECH STACK
==================================================

Backend:
- Python 3.12+
- FastAPI
- SQLAlchemy 2.x
- Pydantic v2
- SQLite for initial development
- Alembic for database migrations
- JWT authentication
- Passlib / bcrypt or Argon2 for password hashing
- Uvicorn
- python-multipart for file uploads

Database:
- SQLite initially
- Structure the project so that PostgreSQL can be introduced later with minimal code changes.
- Do NOT use SQLite-specific SQL wherever avoidable.
- Use SQLAlchemy ORM.
- Use environment variables for DATABASE_URL.

Future database:
PostgreSQL

API documentation:
- Swagger/OpenAPI through FastAPI
- ReDoc
